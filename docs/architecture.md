# ساختار برنامه

ساختار بر پایه پوشه‌های از پیش موجود `app / core / features / shared` است.

```text
src/
  main.tsx                       # اتصال React به DOM
  app/
    App.tsx                      # رندر مسیرها
    providers/AppProviders.tsx   # Redux، persistence، auth و theme
    router/Router.tsx            # ترکیب routes عمومی featureها
    layouts/                    # پوسته، هدر و منوی موجود برنامه
    store/                      # ترکیب reducerها و تنظیمات پوسته
    styles/                     # فونت، متغیرهای theme و Tailwind
    theme/                      # پشتیبانی از تنظیمات ظاهر فعلی
  core/
    api/                        # اتصال HTTP و زیرساخت mock فعلی
    auth/                       # نشست، نقش‌ها، مجوزها و guard
    config/                     # آدرس سرویس‌ها
    socket/                     # اتصال و چرخه اعلان‌ها
  features/
    dashboard/
      index.ts                  # API عمومی feature
      routes.tsx                # مسیرهای پنل و داشبورد عملیاتی
      pages/                    # صفحات ورودی
      components/               # اجزای اختصاصی داشبورد
      hooks/                    # وضعیت، جست‌وجو و علاقه‌مندی‌ها
      model/                    # مدل و توابع تبدیل داده
      styles/                   # CSS Modules این قابلیت
    auth/                       # صفحات و فرم‌های ورود
    access-management/          # کاربران، نقش‌ها و عملیات
    reference-data/              # اطلاعات پایه
    drivers/                    # رانندگان
    vehicles/                   # ناوگان و سوخت
    orders/                     # سفارش‌ها
    warehouse/                  # انبار
    operations/                 # کارگاه، شبکه، درخواست و انتقال
    projects/                   # پروژه و برنامه‌ریزی
    tenders/                    # مناقصه
    human-resources/            # منابع انسانی
    education/                  # آموزش
    reports/                    # گزارش‌ها
    notifications/              # مدیریت اعلان‌ها
    ai-agent/                   # دستیار، hookها، مدل‌ها و اجزای آن
    ...                         # سایر قابلیت‌ها و مثال‌های قالب قبلی
  shared/
    components/
      ui/                       # اجزای عمومی shadcn/ui
      compat/                   # پل سازگاری صفحات منتقل‌شده
      form-controls/            # کنترل‌های فرم مشترک قبلی
    hooks/
    utils/
    types/
    assets/
```

## قواعد توسعه

- صفحه، hook، مدل و اجزای مختص یک قابلیت داخل همان feature قرار می‌گیرند. پوشه خالی صرفاً برای تکمیل یک الگو ایجاد نمی‌کنیم.
- اجزای `shared/components/ui` فقط قرارداد رابط عمومی دارند؛ API، نقش کاربر، store یا قواعد یک قابلیت را نمی‌شناسند.
- مسیرهای هر قابلیت در `routes.tsx` همان feature تعریف و از `index.ts` صادر می‌شوند. Router اصلی از API عمومی قابلیت‌ها استفاده می‌کند.
- اجزای عمومی نباید به `app` یا `features` وابسته باشند. تنظیمات نمایشی مورد نیاز کارت‌های قدیمی از theme دریافت می‌شوند.
- تنظیمات و ارتباطات زیربنایی در `core` هستند. فایل‌های مربوط به یک قابلیت، مانند Redux slice، mock data و typeهای آن، کنار همان قابلیت نگهداری می‌شوند.
- برای کد جدید از shadcn/ui و Tailwind استفاده کنید؛ استایل اختصاصی قابلیت در CSS Module همان قابلیت قرار می‌گیرد.
- در این مهاجرت، فایل‌های بزرگ قدیمی و اتصال‌های بین قابلیت‌ها حفظ شده‌اند. انتقال فایل به feature به معنی تفکیک کامل منطق API و فرمِ تک‌تک صفحات نیست؛ هنگام توسعه همان قابلیت، این تفکیک را تدریجی و با تست انجام دهید.

## جایگزینی MUI

پکیج‌های MUI، Emotion و افزونه RTL حذف شده‌اند. `shared/components/compat` پیاده‌سازی محلی کنترل‌های قبلی با HTML، shadcn و Radix است؛ این پوشه MUI را wrap یا alias نمی‌کند. قرارداد قبلی `sx`، نام کنترل‌ها و callbackها را برای حفظ صفحات موجود نگه می‌دارد. استایل پایه آن CSS Module است و style objectهای قدیمی در همان مرز به CSS تبدیل می‌شوند.

این مرز صرفاً برای کد منتقل‌شده است. پنل جدید از `shared/components/ui` استفاده می‌کند. تغییرات عمده در compat باید با آزمون‌های رفتار فرم همراه باشند. date pickerها اکنون کنترل بومی مرورگرند و همچنان `Date | null` برمی‌گردانند؛ ظاهر تقویم به مرورگر وابسته است.

## پنل جدید

مسیر `/admin` در پوسته و منوی فعلی برنامه اضافه شده است. منوها و مجوزها از `core/auth` دریافت می‌شوند و آمار ساختگی نمایش داده نمی‌شود. جست‌وجوی بخش‌ها، علاقه‌مندی‌های محلی هر کاربر و خروجی CSV فهرست قابل مشاهده در feature داشبورد قرار دارند. داشبورد عملیاتی در مسیر قبلی `/dashboards/dashboard` حفظ شده است.

## بررسی‌ها

```sh
npm run check:architecture
npm run typecheck
npm run build
npm run test:ui
```

تست مرورگر به Chromium نصب‌شده توسط Playwright نیاز دارد (`npx playwright install chromium`). تست‌های پنل از پاسخ‌های API کنترل‌شده استفاده می‌کنند و جای آزمون یکپارچه با سرور واقعی را نمی‌گیرند. پوشش فعلی شامل کنترل‌های مشترک، ورود و guard، منوی مجاز، پنل، موبایل و بارگذاری یک قابلیت قدیمی است.
